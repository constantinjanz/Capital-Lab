# Known limitations

- Docker and the Supabase CLI are required to execute local database/pgTAP tests; application mock mode does not require them.
- The mock weekday calendar remains for local fixtures only. The manual hosted paper-cycle envelope consumes the fixed official 2026 XNAS/ARCX regular-session manifest only to choose a safe skipped outcome; no calendar beyond 2026 exists.
- Vercel snapshot polling is bounded to scheduled decision points and is not a low-latency feed.
- Hosted technical features currently use only the latest 21 eligible completed one-minute bars per feed. They cover spread, short returns, relative volume, five-minute realized volatility, SMA distance, and a documented typical-price VWAP proxy; official-session gap, sector, and broader-market-relative features remain unavailable until calendar-aware feature wiring exists. Features are derived read-only and are not yet pinned in a persisted decision-context snapshot or consumed by the manual cycle envelope.
- Free Alpaca IEX coverage is a single exchange and may not represent the full US market.
- Official-source adapters are allowlisted foundations; operators must review each source's current terms, licensing, rate limits, retention, and user-agent requirements before activation.
- Social/political platform adapters, Sol escalation, controlled web research, and weekly AI meta-review are disabled.
- Options, futures, crypto, FX speculation, and other complex assets are non-tradable placeholders.
- Mock embeddings are deterministic test fixtures, not production semantic embeddings.
- The hosted Supabase schema and generated types are connected. Owner-only draft creation uses fixed EUR 100000.00000000 paper-only defaults, durable idempotency, disabled controls, and immutable audit evidence. Draft names/objectives have a separate revision-checked boundary. A clean draft can now lock the complete reviewed simulator, long-only risk, disabled routing, runtime-off data-source, disabled prompt, empty corpus, bounded budget, five-symbol universe, and official 2026 calendar manifest atomically into `replay` or `shadow`. Start creates only the immutable version, paper account, opening ledger entry, and initial snapshot; it does not itself launch a cycle, enable ingestion/scheduler/agent behavior, call Alpaca or OpenAI, or create an order or fill. Locked experiments separately support explicit shadow-to-live-paper simulation promotion, pause, resume, completion, and clone-to-disabled-draft. Active replay/shadow experiments have a separate manual envelope that consumes a reviewed decision boundary and writes only skipped scheduler/simulator evidence. One atomic hosted market statement reads current configuration and owner-scoped evidence at a database-stamped boundary, while a separate statement attests the fixed calendar. A separate manual owner action can ingest only the reviewed five-symbol Alpaca IEX quote/completed-bar batch when explicitly configured and enabled; it is not the cycle envelope. The view is not a historical configuration browser: universe membership is not bitemporal, the fixed 2026 calendar cannot represent later official revisions in place, and provider-health freshness has no configured threshold. No real OpenAI call or broker call is enabled.
- Protected live Supabase authentication is wired and the confirmed identity is bound as the singleton owner. Application registration/bootstrap, project-level signup, manual identity linking, and anonymous sign-in are disabled; email confirmation remains enabled. Leaked-password protection remains unavailable on the current Supabase Free plan, so the owner should use a unique password; the application does not yet expose MFA enrollment. In Supabase mode, the shell, dashboard landing state, experiment/control list, experiment detail, and market snapshot use owner-scoped hosted reads and never fall back to fixtures. Financial market/detail values and control/draft revisions remain exact strings. Portfolio, cost, and remaining feature pages stay mock/read-only until their precision-safe views and reviewed write use cases replace them.
- The checked-in cron route still runs only the bounded mock-safe cycle. Hosted active replay/shadow experiments have a separate owner-triggered database envelope with official-session checks, slot locking, idempotency, and skipped simulator journaling; it deliberately performs no ingestion, AI, decision, proposal, order, fill, position, ledger, or P&L work. Do not enable a remote scheduler or compose proposal-to-simulated-order execution before those separate reviews.
- The Luna/Terra/Sol orchestrator, deterministic risk engine, and simulator are tested as separate safe boundaries. Live-paper proposal-to-simulated-order composition is intentionally not enabled until the durable database adapters are connected and reviewed.
- The in-memory manual rate limiter is for single-process local development; a distributed deployment needs database- or platform-backed enforcement.
