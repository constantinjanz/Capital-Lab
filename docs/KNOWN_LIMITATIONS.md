# Known limitations

- Docker and the Supabase CLI are required to execute local database/pgTAP tests; application mock mode does not require them.
- The mock weekday calendar is for local fixtures only. Live scheduling must query versioned official market-session rows, including holidays and shortened sessions.
- Vercel snapshot polling is bounded to scheduled decision points and is not a low-latency feed.
- Free Alpaca IEX coverage is a single exchange and may not represent the full US market.
- Official-source adapters are allowlisted foundations; operators must review each source's current terms, licensing, rate limits, retention, and user-agent requirements before activation.
- Social/political platform adapters, Sol escalation, controlled web research, and weekly AI meta-review are disabled.
- Options, futures, crypto, FX speculation, and other complex assets are non-tradable placeholders.
- Mock embeddings are deterministic test fixtures, not production semantic embeddings.
- The hosted Supabase schema and generated types are connected. Owner-only draft creation uses fixed EUR 100000.00000000 paper-only defaults, durable idempotency, disabled controls, and immutable audit evidence. Draft names and objectives are editable through a separate revision-checked, idempotent, audited boundary that cannot change capital, controls, lifecycle, execution, or lock state. One atomic hosted market statement reads the current configuration, owner-scoped quote/bar revisions, sessions, and source health at its database-stamped boundary with exact decimal strings and truthful empty states; it does not ingest data or call a provider. It is not a historical configuration browser: universe membership is not bitemporal, source health uses `created_at` as its temporary availability boundary, calendar rows cannot yet represent revisions, and provider-health freshness has no configured threshold. No hosted experiment or market evidence currently exists, and no real OpenAI call, market-data call, or broker call is enabled.
- Protected live Supabase authentication is wired and the confirmed identity is bound as the singleton owner. Application registration/bootstrap, project-level signup, manual identity linking, and anonymous sign-in are disabled; email confirmation remains enabled. Leaked-password protection remains unavailable on the current Supabase Free plan, so the owner should use a unique password; the application does not yet expose MFA enrollment. In Supabase mode, the shell, dashboard landing state, experiment/control list, experiment detail, and market snapshot use owner-scoped hosted reads and never fall back to fixtures. Financial market/detail values and control/draft revisions remain exact strings. Portfolio, cost, remaining feature pages, and lifecycle transitions beyond draft creation and metadata editing stay mock/read-only until their precision-safe views and reviewed write use cases replace them.
- The checked-in cron route runs the bounded mock-safe cycle. The database contains official-session, scheduler-lock, idempotency, budget, and pause primitives, but those durable functions must be wired into the runtime cycle after database tests pass. Do not enable a remote scheduler before that review.
- The Luna/Terra/Sol orchestrator, deterministic risk engine, and simulator are tested as separate safe boundaries. Live-paper proposal-to-simulated-order composition is intentionally not enabled until the durable database adapters are connected and reviewed.
- The in-memory manual rate limiter is for single-process local development; a distributed deployment needs database- or platform-backed enforcement.
