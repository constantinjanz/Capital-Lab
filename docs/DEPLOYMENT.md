# Deployment

1. Run all local quality gates and review `docs/KNOWN_LIMITATIONS.md`.
2. Create a Supabase project and apply committed migrations; never edit the dashboard as the schema source of truth.
3. Configure the public URL/publishable key pair in Vercel. Add a secret key only when a reviewed server-side adapter needs it; never expose it through a `NEXT_PUBLIC_` variable.
4. Configure the expected email once in `private.owner_bootstrap_config`; set server-only `OWNER_EMAIL`, `OWNER_BOOTSTRAP_ENABLED=true`, and `APP_BASE_URL` to the protected preview origin; and add that origin to Supabase Auth's allowed redirect URLs. Then let that person create and confirm the account from the login page. Their first successful sign-in calls the guarded singleton bootstrap RPC. Verify the matching `auth.users`/`app_users` UUID, confirm a second authenticated user is denied, set `OWNER_BOOTSTRAP_ENABLED=false`, disable new-user signups in the hosted Supabase Auth settings, and redeploy. The application flag does not disable the project-level Auth API.
5. Keep `MARKET_DATA_PROVIDER=mock` and omit Alpaca credentials by default. For the reviewed manual data-only path, first apply the committed migration and pass the database/security gates. Then configure data-only credentials server-side, set `MARKET_DATA_PROVIDER=alpaca`, `ALPACA_DATA_FEED=iex`, `SCHEDULER_PROVIDER=manual`, and keep `AGENT_ENABLED=false`. The owner must still enable the exact source and submit each bounded batch from Markets; credentials or environment flags alone make no request. Never put Alpaca credentials in `NEXT_PUBLIC_*`, Supabase, source control, or logs.
6. After the official-calendar migration passes CI, let the authenticated owner save the fixed 2026 XNAS/ARCX calendar from Markets and verify the database attests 522 sessions while both official provenance sources remain disabled. After the manual-cycle migration separately passes every application/database/Preview gate, the owner may submit one exact-confirmation envelope from an active replay/shadow experiment. Verify it creates only one skipped scheduler run and one skipped simulator journal for the 15-minute slot. Keep remote scheduling disabled; Vercel or Supabase scheduling requires a later reviewed activation and exactly one provider.
7. Keep the agent disabled through database/security/reconciliation review. Enable shadow mode before any live-paper simulation.

Automatic Vercel Git Preview deployments are enabled for non-`main` branches. The `main` branch remains disabled in `vercel.json`, so reviewed changes do not create or promote a Production deployment. Continue using protected branch previews; change the `main` mapping only when Production promotion is explicitly approved.

Required initial hosted configuration: Supabase URL and publishable key, private expected-owner email data, and the temporary server-only owner bootstrap variables. A random 16+ character cron secret becomes required only when a remote scheduler is deliberately enabled. Supabase secret and OpenAI keys are not required. Alpaca Market Data keys are optional and are used only by the separately enabled manual IEX ingestion path.
