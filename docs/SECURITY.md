# Security

> **PAPER TRADING ONLY. No brokerage account, order forwarding, or real-trade credential is supported.**

Supabase email/password auth allows one permanent owner. `OWNER_EMAIL` gates the temporary registration action, while the same expected address is stored separately in an RLS-protected private singleton. The authenticated bootstrap function derives identity from `auth.uid()`, requires a confirmed matching email, serializes competing requests with a transaction advisory lock, and inserts the only possible `app_users` row. Client metadata and submitted owner flags are never trusted. Disable `OWNER_BOOTSTRAP_ENABLED` after provisioning and separately disable new-user signups in the hosted Supabase Auth settings; the application flag cannot close the project-level Auth endpoint. `proxy.ts` refreshes signed sessions, while every Server Action and Route Handler independently authorizes its caller.

Every exposed table has RLS and explicit grants. Policies include ownership; authenticated alone is insufficient. UPDATE policies have both `USING` and `WITH CHECK`. Privileged security-definer functions live in a private schema with fixed search paths and revoked PUBLIC execute privileges. Views are security-invoker.

Hosted experiment writes use narrow public security-invoker RPCs backed by private security-definer implementations. Draft metadata updates derive ownership from `auth.uid()`, lock rows in a consistent order, require an exact expected revision, accept only name and objective, and record redacted audit metadata plus a durable idempotency result. Locked lifecycle mutations use a separate action allowlist for explicit shadow-to-live-paper simulation promotion, pause, resume, completion, and clone-to-disabled-draft. They lock controls before the experiment and simulation account, require the exact control revision, bind retries to an immutable request hash, and reject operation-UUID reuse with changed input. Promotion additionally requires the exact phrase and locked version; completion rejects every non-terminal simulated order state. Clone records source provenance but cannot inherit a lock or runtime state. Server Actions independently reauthorize the owner, and the client receives only IDs, state/version labels, availability booleans, and fresh operation UUIDs. Authenticated clients retain no direct experiment-table mutation privilege.

Hosted market reads use one public owner-only `security invoker` aggregate function with a fixed search path and explicit execute grant. It materializes configuration and evidence in one PostgreSQL statement snapshot, derives the owner from `auth.uid()`, retains RLS, and delegates to bounded read components that reject anonymous/non-owner and future/null decision timestamps and return financial numerics as exact text. Mutable reference metadata outside the boundary fails closed. Quote/bar cancellation, completion, provider-event, and provider-receipt checks are evaluated only after the latest available logical revision is selected. The application validates owner, timestamp, completeness, exact decimals, timezones, exchange consistency, current-day session evidence, and OHLC invariants again before rendering and never falls back to mock data in Supabase mode. Failures emit only a sanitized operation and error class to structured server logs.

Deterministic feature inputs use a separate bounded owner-only invoker component inside that same aggregate statement. It returns at most 21 one-minute bars per selected feed, grants no table mutation, and applies the same latest-logical-revision-before-eligibility rule so cancellations or future-received corrections cannot resurrect older evidence. Pure domain code accepts only canonical decimal strings, validates one-minute windows/OHLC/continuity again, and emits versioned decimal strings or null; it never receives credentials or provider access.

Manual hosted market mutations are owner-only Server Actions over narrow authenticated RPCs. The database rechecks `auth.uid()`, the exact reviewed manifest and source policy, operation UUID, bounded completed window, five-symbol quote set, completed one-minute bars, exact decimal strings, request metadata, and sanitized failure class. Provider HTTP occurs outside short transactions; commits append revisions and database-stamp availability. Authenticated clients retain no direct write privilege. The adapter refuses redirects, bounds symbols, pages, records, bytes, per-request time, and aggregate batch time, and can reach only the Alpaca data origin. Credentials never cross the client boundary or enter persistence/audit payloads.

Secrets stay server-side and are filtered from structured logs. Health checks reveal status, not secret values. Manual agent/cycle endpoints are owner-only and rate-limited. External content is sanitized and delimited as untrusted data.

Run `pnpm test:safety` to scan for forbidden brokerage hosts, endpoints, SDKs, and credential names. Treat a failure as a release blocker.
